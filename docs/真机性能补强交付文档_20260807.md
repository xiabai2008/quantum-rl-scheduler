## 一、本次核心成果

### 1.1 重大 Bug 修复：真机测量结果解析失败（fidelity 恒为 0）

**这是本次最重要的发现**。历史上所有真机实验的 `fidelity` 都是 0，导致：

- `result_aware` 模式下的真机 reward 全部无效（恒等于最小值）
- 真机反馈从未真正进入训练/评估信号
- 答辩口径"真机 reward 占比极低（1/96步）"的根因之一

**根因**：`cqlib` 返回的任务结果中，测量分布位于 `raw.resultStatus` 字段（嵌套列表格式 `[[0],[1],[1],...]`），但 `parse_measurement_result`（`src/scheduler/env_real_machine.py`）只处理：
- `probability` 字典（cqlib 返回为空）
- `counts` 字典（cqlib 返回为空）
- `resultStatus` **字符串** JSON（cqlib 实际返回的是**嵌套列表**，不匹配）
- `result` 字段（cqlib 的 result 是 probability 的镜像，同样为空）

**修复**（`src/scheduler/env_real_machine.py`）：
1. 新增 `_result_status_to_counts()`：支持嵌套列表 `[[0],[1],...]` → 计数字典
2. 路径 3 扩展：`resultStatus` 支持 list 类型；字符串形式也走统一转换
3. 新增 `raw.resultStatus` 提取：cqlib 把原始 data 塞进 `raw` 字段，需提取后再解析

**端到端验证**（真实任务 2085616985975242753）：
```
修复前: probability={} → fidelity=0.0000, reward=0.0000
修复后: {'0': 0.062, '1': 0.938} → fidelity=0.8788, reward=4.3939
```

**附带发现**：tianyan176 的 H 门测量严重偏斜（P(1)=93.8% vs 理论 50%），这是真实的机器噪声表现，反而支撑"噪声对 AI 的挑战"叙事——但要在答辩中如实说明，避免被指"保真度数据质量差"。

## 四·B、平台深入调研结论（15:00-15:30 补充）

### 4B.1 排除了的假设

| 假设 | 验证方式 | 结论 |
|---|---|---|
| 机器名不匹配（176 vs 176-2） | `attach_real_clients` 按名匹配已核对 | ❌ 排除，176-2 是机构专属无权限，176 正常 |
| Q0 电路不被支持 | 手动提交 Q0/Q1 对照（H/X/RX 各 1 次） | ❌ 排除，Q0 也能成功，失败与 Q0/Q1 无关 |
| 提交阶段失败（task_id 拿不到） | 15:09 连续 5 次提交 | ❌ 排除，提交阶段 5/5 拿到 task_id |
| 客户端预检误判（状态查询不一致） | `list_backends()` vs `_is_machine_available()` 对照 | ❌ 排除，176 状态 running，预检放行 |

### 4B.2 确认的事实：失败发生在执行阶段，且时段波动

- **提交成功率 ≈ 100%**（拿到 task_id），**执行成功率 ≈ 15-20%**（"Run failure"）
- 平台对失败任务不返回细节（`query_experiment` 无错误原因，raw 为空）——黑盒
- **时段波动极大**：15:09 手动低频提交 5/5 全部执行成功（平衡度 0.727-0.970）；15:14 后 env 高并发提交又大面积失败
- 失败是**随机分布**的，不特定于电路/机器/策略

### 4B.3 已做的加固：RetryClient

`run_real_performance_v3.py` 新增 `RetryClient` 包装（提交失败重试 2 次，间隔 1.5s）：
- 只包装 `submit_quantum_task`，其余透传；隔离在实验脚本内，不动 src
- **效果有限**：因为失败在执行阶段（提交已成功），重试提交无法解决执行失败
- 保留该包装（对提交阶段偶发失败仍有帮助），但不要指望它解决核心问题

### 4B.4 pilot 数据质量（3 seeds × 3 策略实测）

| 指标 | 结果 |
|---|---|
| 成功任务保真度 | 优秀：fid 0.848-1.0，reward 4.2-5.0（链路完全正常） |
| 执行成功率 | ~15%（30 次提交仅 4-5 次执行成功） |
| 策略间 reward 差异 | 被失败惩罚噪声淹没，不可用于统计检验 |

### 4B.5 结论：tianyan176 不适合做高参与率性能实验

- 失败噪声（~85%）远大于策略差异（+20.2% 量级），统计功效不足
- 硬跑 N=20×3 只会产出**不可信甚至伪显著**的结果，损害项目诚信
- 176 只适合：可用性验证、小样本探索、链路验证
