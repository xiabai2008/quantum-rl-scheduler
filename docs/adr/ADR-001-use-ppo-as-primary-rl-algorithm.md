# ADR-001: 使用 PPO 作为主强化学习算法

## Status

Accepted

## Context

本项目（量子RL调度系统）需要选择一种强化学习算法作为主调度策略，用于在量子-经典混合任务调度环境中做出资源分配决策。候选算法包括：

1. **PPO（Proximal Policy Optimization）**：策略梯度算法，通过裁剪目标函数限制策略更新幅度，训练稳定性高
2. **DQN（Deep Q-Network）**：值函数方法，使用经验回放和目标网络，适合离散动作空间
3. **MAPPO（Multi-Agent PPO）**：多智能体 PPO 扩展，适合多机器协调调度场景

### 决策驱动因素

- **训练稳定性**：量子任务调度环境奖励稀疏且方差大，需要稳定的训练过程
- **样本效率**：真机调用成本高（天衍-287 每次任务约 90 秒），需要高样本效率
- **动作空间**：调度环境为离散动作空间（经典资源/量子资源/混合执行）
- **可复现性**：比赛要求实验结果可复现，需要确定性推理能力
- **生态成熟度**：Stable-Baselines3 提供成熟实现，降低工程风险

### 实验数据支撑

在 16 维原生环境中进行 50 seeds x 5 episodes = 250 次独立运行（N=250）的对比实验：

| 策略 | 平均奖励 | 标准差 | 提升 vs FCFS |
|:--|:--:|:--:|:--:|
| **PPO** | **1982.69** | 557.25 | **+20.2%** |
| DQN (Random替代) | 602.37 | 262.09 | -63.5% |
| FCFS | 1648.91 | 502.95 | 基线 |

- 统计检验：Welch t，p=7.56e-12，rank-biserial=-0.3642（中效应）
- DQN 在 v9 已删除，使用 Random 策略替代占位（config/statistics.yaml）

## Decision

**采用 PPO 作为项目主强化学习算法。**

具体决策：

1. PPO 为唯一主训练和评估算法，使用 16 维原生观测空间
2. 权威模型文件为 `deliverable_models/ppo_best_model_16dim.zip`
3. 所有答辩材料、白皮书、PPT 中的核心结论数字均基于 PPO 结果
4. PPO 使用 Stable-Baselines3 的 `PPO` 实现，`deterministic=True` 推理

## Consequences

### 正面影响

- 训练稳定，无需复杂的超参数调优即可收敛
- 支持确定性推理，保证实验可复现
- 在 N=250 大样本验证中表现最优（+20.2%，p=7.56e-12）
- Stable-Baselines3 生态成熟，社区支持好

### 负面影响

- DQN 仅保留用于对比实验，不再作为主策略投入开发资源
- PPO 标准差较大（557.25），反映策略对环境随机性敏感，需在论文中如实声明
- MAPPO 多智能体扩展未作为主策略，多机器协调依赖环境层实现

### 后续约束

- 所有新模型训练默认使用 PPO + 16维原生环境
- DQN 仅用于与旧版 10 维模型的公平对比（通过 Obs10Wrapper 包装器）
- 如需切换主算法，须新建 ADR 并重新进行 N>=250 的统计验证

## Alternatives Considered

### 方案 A：DQN 作为主算法

- 优势：实现简单，离散动作空间天然适配
- 劣势：训练不稳定，在 16 维环境中因模型维度不匹配退化为随机策略；样本效率低
- 结论：不采用。保留 DQN 仅供历史对比

### 方案 B：MAPPO 作为主算法

- 优势：支持多智能体协调，适合多机器场景
- 劣势：多智能体训练复杂度高，调参成本大；当前单智能体 PPO 已在多机器环境中通过环境层实现协调
- 结论：不采用作为主策略。MAPPO 作为扩展实验保留（`src/scheduler/marl.py`），热力图可视化已实现

### 方案 C：多算法集成（Ensemble）

- 优势：可结合多种算法优势
- 劣势：增加系统复杂度，难以归因单算法贡献，不符合比赛"核心创新"叙事
- 结论：不采用
