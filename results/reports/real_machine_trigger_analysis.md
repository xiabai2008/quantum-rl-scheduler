# 真机提交概率触发未命中根因分析报告

> **Issue**: #242 — 排查概率触发未命中根因
> **关联 Issue**: #243 — 真机提交从概率触发改为间隔触发
> **诊断日期**: 2026-07-27
> **诊断脚本**: `scripts/testing/diagnose_rng_trigger.py`

## 1. 诊断背景

在多seed真机实验中，使用 `real_submit_probability=0.05`（5%概率触发）时，部分 seed 出现真机参与率为0%的异常。PR #316 通过实验脚本层面的调整（每组强制1次真机任务）验证了10/10 seeds的真机参与率100%，但代码层面的 `env_machines.py` 仍只有概率触发逻辑。

本诊断旨在排查概率触发未命中的根因，为 #243 的间隔触发修复提供依据。

## 2. 诊断方法

### 2.1 诊断1: RNG 序列命中统计

对10个seed（与多seed实验一致：`[42, 123, 456, 789, 1024, 2025, 3141, 5678, 8765, 9999]`），模拟前1000步的 `rng.random()` 序列，统计 `< 0.05` 的命中次数。

### 2.2 诊断2: 实际路由机会与零命中概率

使用固定 QUANTUM 动作（最大化进入 `route_to_machine()` 的机会），统计实际进入真机提交分支的条件满足次数（`select_best_machine()` 返回非 None），并计算 `P(0次命中) = (1-p)^N`。

### 2.3 诊断3: RNG 初始化与状态重置检查

- 检查相同 seed 的两次 `reset()` 是否产生相同的第一个随机数（验证 SeedSequence 正确派生）
- 检查 `env.np_random` 对象 ID 在 step 循环中是否被重新赋值（验证无意外重置）

## 4. 根因分析结论

### 4.1 不是 RNG Bug

RNG 初始化使用 Gymnasium 标准的 `SeedSequence` 派生机制，所有 seed 的初始化均正确。原始 `rng.random()` 序列的命中次数接近期望值，RNG 状态在 step 循环中未被意外重置。

### 4.2 核心根因：概率触发的三重过滤效应

真机提交的 `route_to_machine()` 中的概率触发分支需要同时满足以下条件：

```
条件1: machine.is_real == True          （机器为真机模式）
条件2: machine.name in env._real_clients （已绑定真机客户端）
条件3: env.real_submit_probability > 0.0  （概率阈值 > 0）
条件4: rng.random() < real_submit_probability  （概率命中）
```

**条件1-3** 是前置过滤，只有满足时 `rng.random()` 才会被调用。但前置过滤的效果极其严重：

1. **任务-机器兼容性过滤**：`select_best_machine()` 要求机器在线、可用比特数 >= 任务需求、支持任务所需门集合。随机生成的任务经常因比特数不足或门不兼容而被过滤掉。
2. **动作类型过滤**：只有 `action == QUANTUM(1)` 或 `HYBRID(2)` 时才调用 `route_to_machine()`。
3. **概率门控**：即使前三层过滤通过，`rng.random() < 0.05` 只有 5% 命中概率。

**三重过滤的叠加效应**：当实际路由机会数 N 极少（0-8次/1000步）时，P(0次命中) = (1-0.05)^N 极高：

| 路由机会数 N | P(0次命中) | 含义 |
|------------:|----------:|------|
| 0 | 100% | 必然完全错过 |
| 1 | 95.0% | 几乎必然错过 |
| 3 | 85.7% | 高概率错过 |
| 8 | 66.3% | 2/3 概率错过 |
| 30 | 21.5% | 1/5 概率错过 |
| 50 | 7.7% | 接近不影响 |

### 4.3 为什么 PR #316 的脚本层面修复有效

PR #316 在实验脚本中使用 `real_submit_probability=0.0`（完全禁用概率触发），改为在脚本层面按间隔强制提交：

```python
if step % REAL_SUBMIT_INTERVAL == 0 and real_tasks_submitted < MAX_REAL_TASKS_PER_RUN:
    record = _submit_and_poll_one_task(...)
```

这种方式绕过了 `route_to_machine()` 的三重过滤，直接在脚本层面控制提交时机，确保每组至少1次真机任务。

## 5. 修复方案（Issue #243）

### 5.1 间隔触发保底 + 概率触发额外增加

在 `route_to_machine()` 中增加间隔触发逻辑：

```python
should_submit = False
if machine.is_real and machine.name in env._real_clients:
    if env._current_step % env.real_submit_interval == 0:
        # 间隔触发：每N步强制提交一次（保底）
        should_submit = True
    elif env.real_submit_probability > 0.0 and float(rng.random()) < env.real_submit_probability:
        # 概率触发：额外增加提交机会
        should_submit = True
if should_submit:
    env._submit_to_real_machine(...)
```

### 5.2 配置参数

| 参数 | 默认值 | 说明 |
|-----|-------|------|
| `REAL_MACHINE_SUBMIT_INTERVAL` | 20 | 每20步强制提交一次（env_types.py 常量） |
| `real_submit_interval` | 20 | env.py 构造函数参数 |
| `real_submit_interval` | 20 | config.yaml quantum 配置节 |

### 5.3 预期效果

- 间隔触发确保每20步至少1次真机提交机会（前提是任务-机器兼容性通过）
- 概率触发作为额外增加，不删除原有逻辑
- 两者共存，互不影响
- 预期真机参与率从 ~10% 提升至 100%（在任务-机器兼容的前提下）
